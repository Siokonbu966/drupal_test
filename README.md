# Drupal Notes Web App - ディレクトリ構成と設計解説

このプロジェクトは、Drupal 11をバックエンドにしたメモ帳Webアプリケーションです。
Drupalの学習に役立つよう、このプロジェクトのディレクトリ構成や、それぞれのファイル・フォルダがDrupal環境においてどのような役割を担っているのかを詳細に解説します。

---

## 開発環境の構築 (他環境でのセットアップ手順)

このプロジェクトを別の環境にクローンして開発を始める場合は、以下の手順でセットアップを行います。

### 1. 前提条件の用意
このプロジェクトは **PHP 8.3**、**Composer**、**SQLite** を使用します。

* **Nix を使用する場合 (推奨)**
  Nix がインストールされている環境であれば、必要なツール群はすべて `flake.nix` を通じて自動的に用意されます。
* **手動でインストールする場合**
  使用するPCに PHP 8.3、Composer、SQLite を直接インストールしてください。

### 2. セットアップスクリプトの実行
プロジェクトルートにあるセットアップスクリプトを実行し、書き込み用のディレクトリ作成と設定ファイル (`settings.php`) の初期設定を自動で行います。

```bash
./setup.sh
```

### 3. 依存関係のインストール (ビルド)
Drupal コアやパッケージをインストールします。

* **Nix を使用する場合**:
  ```bash
  nix develop --impure -c composer --working-dir=drupal-app install
  ```
* **手動でインストールする場合**:
  ```bash
  cd drupal-app
  composer install
  ```

### 4. 開発サーバーの起動
セットアップが完了したら、開発サーバーを起動してブラウザからアクセスします。

```bash
# プロジェクトルートで実行 (Nix環境下で自動的にPHPサーバーが立ち上がります)
./run-server.sh
```
※ Nix を使用しない場合は、`cd drupal-app/web && php -S 127.0.0.1:8080 .ht.router.php` で手動起動してください。

起動後、**http://127.0.0.1:8080** にアクセスして動作を確認します。管理画面（`/user`）の認証情報は `admin / admin` です。

## 1. 全体ディレクトリ構造

プロジェクトのルートディレクトリから見た主要なフォルダ構造は以下の通りです。

```text
test_antigravity/                     # プロジェクトのルート (Workspace Root)
├── flake.nix                         # Nix環境定義ファイル
├── flake.lock                        # Nix依存関係のロックファイル
├── run-server.sh                     # 開発サーバー起動用スクリプト
└── drupal-app/                       # Drupalプロジェクト本体 (Composerプロジェクト)
    ├── composer.json                 # PHPのパッケージ依存管理ファイル
    ├── composer.lock                 # パッケージの正確なバージョンロック
    ├── vendor/                       # Composerがダウンロードしたライブラリ（DrushやSymfonyコンポーネント等）
    └── web/                          # Webサーバーのドキュメントルート (公開領域)
        ├── index.php                 # すべてのリクエストの入り口 (Front Controller)
        ├── .ht.router.php            # PHP組み込み開発サーバー用のルータースクリプト
        ├── .htaccess                 # Apache用設定（リライトルール、セキュリティ）
        ├── robots.txt                # 検索エンジンクローラーへの指示ファイル
        ├── core/                     # Drupalのコアプログラム（★絶対に直接変更してはいけない）
        ├── modules/                  # モジュール（機能拡張用）フォルダ
        │   ├── contrib/              # コミュニティ提供の外部モジュール (Composerで管理)
        │   └── custom/               # 自作モジュール (今回の「notes_app」はここ)
        │       └── notes_app/        # メモアプリ機能を提供する自作モジュール
        ├── themes/                   # テーマ（デザイン用）フォルダ
        │   ├── contrib/              # コミュニティ提供の外部テーマ
        │   └── custom/               # 自作テーマ
        ├── profiles/                 # インストールプロファイル (standard, minimal等)
        └── sites/                    # マルチサイト設定およびサイト固有のファイル
            └── default/              # デフォルトサイトの設定フォルダ
                ├── settings.php      # データベース接続や秘密鍵などの主要設定
                ├── files/            # ユーザーがアップロードしたファイルや一時ファイルの保存先
                │   └── .ht.sqlite    # SQLiteのデータベースファイル (本体)
                └── default.settings.php # settings.php作成の雛形
```

## 2. 各ディレクトリとファイルの役割解説

### ① ルート層のファイル群
* **`flake.nix` / `flake.lock`**
  Nixパッケージマネージャーが提供する開発環境定義です。このプロジェクトを実行するのに必要な PHP 8.3、Composer、SQLite などのツールを自動的に引き当て、ローカルPCのグローバル環境を汚さずに独立した実行環境を作っています。
* **`run-server.sh`**
  Drupalをローカルで手軽に動かすために作成したシェルスクリプトです。Drupalのドキュメントルートである `drupal-app/web/` に移動し、PHPのビルトインサーバーと、Drupal用のルータースクリプト（`.ht.router.php`）を起動します。

### ② `drupal-app/` (Composerプロジェクト)
DrupalはPHPのモダンなパッケージ管理ツール **Composer** を使ってインストール・管理することが推奨されています。
* **`composer.json` / `composer.lock`**
  プロジェクトが依存しているライブラリ（Drupalコア、Symfony、Drushなど）が定義されています。Drupalモジュールやテーマを追加する際は、ファイルを直接ダウンロードするのではなく、`composer require drupal/モジュール名` コマンドを使ってインストールします。
* **`vendor/`**
  Composerによってインストールされた、サードパーティ製のPHPライブラリです。Drupalはベースフレームワークとして **Symfony** を採用しており、Symfony由来の多くのコンポーネントがこの中に配置されます。また、DrupalのCUI管理ツールである **Drush** の本体もここに入ります。

### ③ `drupal-app/web/` (ドキュメントルート)
Webサーバーが外部に公開するフォルダです。
* **`index.php`**
  Drupalの「フロントコントローラー」です。ブラウザからのリクエスト（`/notes` や `/api/notes` など）は、すべてまずこのファイルにルーティングされ、そこからDrupalが起動（ブートストラップ）して適切なプログラムへ処理を振り分けます。
* **`core/`**
  Drupalのコアシステム（ユーザー管理、コンテンツ作成、API基盤、基本モジュール群など）がすべて格納されています。
  > [!WARNING]
  > **「Don't Hack Core (コアを改変するな)」の原則**
  > `core` フォルダ内のファイルは絶対に直接編集してはいけません。セキュリティアップデートやバージョンアップの際にすべて上書きされてしまうためです。機能を拡張・変更したい場合は、必ず「customモジュール」や「フック（Hook）」「イベントリスナー」を使って実装します。
* **`modules/`**
  機能を追加・変更する「モジュール」を配置する場所です。
  * **`contrib/`**: `drupal.org` からダウンロードしたコミュニティ製の外部モジュールを配置します（Composerが自動でここにダウンロードします）。
  * **`custom/`**: 自分たちが手書きで作成するモジュール（自作モジュール）を配置します。今回はここに `notes_app` を作成しました。
* **`themes/`**
  見た目やレイアウトをカスタマイズする「テーマ」を配置する場所です。モジュールと同様に `contrib/`（配布テーマ）と `custom/`（自作テーマ）に分かれています。
* **`sites/default/`**
  サイト個別の設定やデータが格納されます。
  * **`settings.php`**:
    最も重要な設定ファイルです。SQLiteデータベースへの接続パスや、セキュリティ用のハッシュソルト（`$settings['hash_salt']`）などが記述されています。
  * **`files/`**:
    Webサーバーが書き込み権限を持つフォルダです。ユーザーが投稿に添付した画像などのアセットが保存されます。今回の構成では、SQLiteデータベース（`.ht.sqlite`）もこの中に安全に作成・格納されています（`.ht` から始まるファイル名は外部からブラウザで直接アクセスできないよう、`.htaccess` などで保護されています）。

## 3. 自作モジュール `notes_app` の内部構成と動作の仕組み

今回作成した [notes_app](file:///home/crocus/src/test_antigravity/drupal-app/web/modules/custom/notes_app/) モジュールは、Drupalの仕組みを学ぶ上で非常に典型的なカスタムモジュールの構造をしています。

```text
notes_app/
├── notes_app.info.yml     # ①モジュールの基本情報定義
├── notes_app.routing.yml  # ②URLと処理（コントローラー）のマッピング
├── notes_app.libraries.yml# ③アセット（CSS/JS）の定義
├── notes_app.install      # ④インストール・アンインストール時のDBセットアップ処理
├── css/
│   └── styles.css         # アプリケーションのスタイルシート
├── js/
│   └── app.js             # メモアプリのフロントエンドJS (SPA)
└── src/
    └── Controller/
        └── NotesController.php # ⑤APIと画面を処理するコントローラー
```

### 動作の流れ（リクエストから表示まで）
1. **リクエスト受信**: ユーザーが `http://127.0.0.1:8080/` にアクセスします。
2. **ルーティング**: `system.site` 設定により、トップページは自動的に `/notes` に転送されます。Drupalのルーターが `notes_app.routing.yml` を参照し、`/notes` に対する処理が `NotesController::index` であることを特定します。
3. **コントローラー実行**: `NotesController::index` が呼び出されます。このメソッドは、フロントエンドSPAを動かすための最小限のHTML（`styles.css` や `app.js` を読み込むヘッダーと、コンテンツを描画する `#app` コンテナ）を生成してブラウザに返します。
4. **JSの起動とAPI呼び出し**: ブラウザで `app.js` が実行されると、JSは即座に `GET /api/notes` へAjaxリクエストを送信します。
5. **API応答**: コントローラーの `getNotes` メソッドが走り、Drupalのエンティティシステムを使用してデータベースから「note」タイプの内容を読み込んでJSON形式で返却します。
6. **DOM描画**: `app.js` が受け取ったJSONデータを使って画面上にメモ一覧を動的に生成します。新規追加や編集、削除の際も、JSから `/api/notes` へ非同期でリクエストを送り、コントローラーが `Node::create` や `delete` などのDrupal標準APIを叩くことで裏側のデータベースが更新されます。

## 4. Drupalを学習する上での重要キーワード

Drupalのドキュメントや解説を読む際、以下の概念を押さえておくと理解がスムーズになります。

* **Entity (エンティティ)**
  Drupalにおけるデータモデルの最小単位です。コンテンツを表す `Node (ノード)`、ユーザーを表す `User`、カテゴリタグを表す `TaxonomyTerm (タクソノミーターム)` などはすべてエンティティです。これらはプログラムから統一されたAPI（`$entity->save()`, `$entity->delete()`など）で操作できます。
* **Bundle (バンドル)**
  エンティティの具体的な種類です。例えば `Node` というエンティティの中に、「記事（Article）」「基本ページ（Page）」「メモ（Note）」といった異なる入力フィールドを持つセット（コンテンツタイプ）を作ることができます。この個々のコンテンツタイプを「バンドル」と呼びます。
* **Routing System (ルーティングシステム)**
  Symfonyコンポーネントをベースにしています。どのURLにアクセスしたときに、どのPHPクラス（コントローラー）を動かすかを `*.routing.yml` で宣言的に定義します。
* **Configuration Management (構成管理)**
  Drupalは「コンテンツ（記事データなど）」と「構成（コンテンツタイプの設定、表示管理、モジュールの有効化ステータスなど）」を明確に分けて管理します。構成情報はYAMLファイルとしてエクスポート（`drush config:export`）し、Gitでバージョン管理して別の環境へインポート（`drush config:import`）することができます。
